WMSO is a research architecture that does not repeatedly solve a long sequence of fine-grained future actions. Instead, a world model predicts and orchestrates which skill to use, how to initialize it, when a handoff is valid, and how to recover from failure.

01 / Core idea

From sequential action plans to prepare-and-release control.

Conventional trajectory optimization arranges several future actions inside a world model and updates them during execution. WMSO raises the planning unit to the skill level: the model evaluates what to start, from which state, and under which conditions.

Sequential action planning

Rebuild a sequence of fine-grained future actions.

aₜ aₜ₊₁ aₜ₊₂ …

Long-horizon optimization becomes high-dimensional, and disturbances or goal changes make an open action sequence stale. Replanning remains useful, but representing everything as low-level actions makes the search space grow rapidly.

The world model predicts skill outcomes and transitions, then compares candidates before commit. Execution is not a frozen action tape; it remains closed-loop through sensor feedback.

02 / Architecture

Prepare, validate, release, execute, and hand off.

WMSO separates tentative internal planning state from committed execution state. During preparation, the active skill or a hold controller continues to stabilize the physical system. A new skill is committed only when its contract is satisfied.

skill-level closed-loop orchestration belief → preparation → commit → execution → handoff / recovery
01

Prepare

Search for a launch condition in an output-null planning workspace.

  • Candidate skills and parameters
  • Desired handoff state
  • Success probability and uncertainty
  • Bridge and recovery candidates
02

Commit gate

Validate the execution contract. If any condition fails, retain the active controller and prepare again.

  • State belongs to the initiation set
  • Handoff compatibility
  • Uncertainty within limits
  • Safety, bundle, and version integrity
03

Release

Transform prepared information into a committed execution bundle that the executor is allowed to read.

  • Fix the skill identity
  • Fix launch state and target
  • Bind controller and monitors
  • Switch atomically
04

Closed-loop execution

Unfold learned skill dynamics while correcting them with observation feedback.

  • Local correction under disturbance
  • Monitor success, failure, and progress
  • Apply safety constraints continuously
  • Stop or recover when required
05

Handoff

Transfer the terminal state to the next skill. Select a bridge or recovery skill when direct chaining is invalid.

  • Evaluate the termination set
  • Transfer state to the next skill
  • Represent no-chain explicitly
  • Begin the next preparation cycle
While preparingThe active skill, hold controller, or impedance controller continues stabilizing the plant.
While executingThe world model updates its outcome forecast and may prepare the next transition in parallel.
On anomaliesExcess uncertainty, contract mismatch, or failure evidence blocks release by default.

“Output-null” means that tentative planning updates cannot directly affect actuator commands before commit. WMSO does not copy a biological null space literally; it reformulates the idea as a software and control boundary.

Pre-commit output isolation

∂at / ∂pprep = 0

Updating preparation state pprep must not change the current action at before commit. This is enforced structurally: the executor does not read tentative planning state.

03 / Safety boundary

Safety must not depend only on learning the right behavior.

World models and policies can be wrong. Candidate generation, contract validation, and execution commit are therefore separated so that an uncommitted inference cannot leak into control output.

  • Keep the execution bundle immutable before commit
  • Predict uncertainty, no-chain, and failure explicitly
  • Do not switch when compatibility or safety conditions fail
  • Retain observation feedback and low-level safety control during execution

04 / What the model predicts

A world model predicts more than the next action.

WMSO treats each skill as a semi-Markov option and predicts its result, duration, failure modes, and chainability from initiation to termination. Long tasks are compressed into a shorter sequence of skill decisions rather than control-cycle decisions.

01 / OUTCOME

Skill outcome

Terminal belief state, object configuration, contact, grasp, tension, and related variables.

02 / TIME & COST

Time and cost

Duration, energy, switching cost, and the cost of changing an active commitment.

03 / FAILURE

Failure and no-chain

Failure modes, states that cannot connect forward, and recovery requirements.

04 / UNCERTAINTY

Uncertainty

Forecast confidence, out-of-distribution state, missing observation, and model disagreement.

05 / HANDOFF

Handoff

Compatibility with the next initiation set and available bridge skills.

05 / Robotics stack

WMSO connects world understanding to physical control.

It receives goals and constraints from high-level task decomposition, then turns them into executable skills. Below it, learned policies, residual reinforcement learning, heuristics, and safety controllers move the physical system in closed loop.

06 / Conceptual origin

From neural geometry to an engineered execution boundary.

The conceptual inspiration is the motor-cortex account in which preparatory activity occupies an output-null space and recurrent dynamics move into output-potent directions after a go cue. WMSO is an engineering proposal that transfers this pattern to model-based reinforcement learning and skill orchestration; it is not a literal implementation of the biological mechanism.
